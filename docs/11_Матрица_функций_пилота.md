# Матрица функций ЭЛИФ: код → пилот → эффект

**Версия:** 0.2 · 18 октября 2026  
**Назначение:** восстановить фактическое использование программных функций в пилоте с Дилярой. Это рабочая форма, которую можно заполнять постепенно. Не указывайте имена детей, телефоны и другие персональные данные.

## Как заполнять

В каждой строке отдельно отмечайте четыре вещи:

1. **Код / реализация:** что, по имеющимся данным, существовало технически.
2. **Использование:** реально ли человек применял это в пилоте.
3. **Работоспособность:** что автор сообщает о текущем состоянии функции (самоотчёт, пока без независимого теста).
4. **Эффект:** что изменилось после использования и есть ли доказательство.

### Значения статуса использования

- U — использовали в пилоте;
- N — функция была доступна, но не использовалась;
- P — была частично реализована;
- D — только задумана / описана в документации;
- F — пытались использовать, но функция не работала;
- ? — пока неизвестно.

Не ставьте статус U только потому, что соответствующая сущность или API есть в коде или автор сообщает, что функция работает.

### Отдельный статус работоспособности

Указанные ниже статусы «Работает» / «Не работает или не готова» передают уточнение автора от 18.10.2026; они не были независимо воспроизведены в рамках ведения этого репозитория. Статус использования в пилоте остаётся отдельным полем.

## Сквозной цикл: один реальный пример

Выберите один конкретный эпизод без персональных данных ребёнка.

| Этап | Что нужно записать |
|---|---|
| 1. Исходная ситуация | Что педагог заметил до открытия программы |
| 2. Фиксация | Какая функция использовалась; что именно сохранилось |
| 3. Интерпретация | Кто сформулировал гипотезу — педагог, руководитель, оператор или ИИ |
| 4. Решение | Какое действие решили попробовать и кто принял решение |
| 5. Реализация | Что произошло на следующем занятии; использовали ли программу |
| 6. Повторное наблюдение | Что увидели после действия; кто это зафиксировал |
| 7. Вывод | Что изменили в понимании ситуации или следующем действии |
| 8. Ручные переходы | Что копировали, пересылали, обсуждали или обрабатывали вне программы |
| 9. Подтверждение | Где находится запись, документ, версия или другой артефакт |
| 10. Ограничение | Что остаётся неизвестным и какие есть альтернативные объяснения |

Если цикл не был завершён, укажите конкретно, на каком этапе он остановился. Это важный результат аудита, а не ошибка заполнения.

## Итоговая сводка после заполнения

По каждой функции должно быть возможно ответить на четыре независимых вопроса:

- **Технически предусмотрена / существует?** Да / частично / нет / не проверено.
- **Работает по сообщению автора?** Да / нет / не уточнено; это не равно независимой проверке.
- **Использовалась в пилоте?** Да / нет / частично / неизвестно.
- **Польза подтверждена?** Да — с каким свидетельством; пока нет; не измерялась.

Не объединяйте эти статусы в общий процент «готовности». Они отражают разные состояния: наличие функции, работоспособность, фактическое использование и доказанную ценность для центра.
